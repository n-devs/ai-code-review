# v2.1.0

## What's changed

- **Inline review comments (`files_changed`)** — set `files_changed: true` to have the AI review each changed file individually and post inline review comments directly on the diff (Files changed tab) instead of one combined PR comment. Each file gets its own AI pass, comments are capped at 20 per run, and if posting the review fails the action falls back to a single PR comment so feedback is never lost.
- **Review by author (`username`)** — scope the review to changes by a specific GitHub username (`username: octocat`). Only files touched by commits authored by that user are reviewed. Use `all` to review everyone, or leave it empty to review changes by the user who triggered the workflow run.
- **Manual run support** — documented a `workflow_dispatch` setup so you can review any PR on demand from the Actions tab with any provider/model, with the `api_key` input masked in run logs.
- **Deploy Release workflow** — releases are now deployed via **Actions → Deploy Release** using the notes in this folder. The deploy is aborted when `docs/release/v<version>.md` does not match the specified version.

## Notes

- Both new inputs are optional: `files_changed` defaults to `false` and `username` defaults to the workflow actor, so existing workflows keep the previous behavior (one combined PR comment on all changes) without any changes.
