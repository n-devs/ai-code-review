# v4.0.0

## What's changed

- **Review memory (`memory: true`)** — the AI no longer starts from scratch on every run:
  - Loads `context.md` (stable, human-edited base knowledge) plus daily memory files `<date>-context.md` from `context_path` (default `.github/ai-review/`) into every agent's prompt.
  - `memory_files` selects which days to load: a number = latest N files (default `3`), specific dates (`2026-10-25,2026-10-28`), or a date range (`2026-10-20..2026-10-28`).
  - Loads the bot's own previous review comments on the PR — it will not re-report already-reported issues, and items fixed by the current diff get a short ✅ acknowledgment instead.
  - After every run, the AI writes a memory summary into **today's** `<date>-context.md` and commits it back to the repo (best-effort, `[skip ci]`); multiple runs on the same day append sections to the same file.
- **Fixed memory schema (code-enforced)** — both file types use locked structures so memory stays machine-readable:
  - `context.md` → `Architecture` / `Skip Review` / `Conventions` / `Known Issues`
  - daily files → each `## Run <timestamp> — PR #N` section always has `Patterns` / `Decisions` / `Follow-ups` / `Fixed` (missing sections are filled with `- none`, stray headings are dropped).
- Ships with a starter `.github/ai-review/context.md` for this repo.

## Notes

- Memory saving needs `contents: write` in the calling workflow; if saving fails (e.g. read-only token) the review still completes normally.
- Default remains `memory: false` for action users — no behavior change unless opted in. The bundled test workflow enables it by default.
- Major version bump because the bundled workflow behavior and memory conventions are new; pin with `n-devs/ai-code-review@v4`.
