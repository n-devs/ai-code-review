# v5.0.0

## What's changed

- **New agent file format — `<name>.agent.md` with frontmatter** — agent definitions now use YAML-ish frontmatter (`name` display label, `description`, `tools`) followed by the persona markdown body. The file name is the agent id referenced in `agents`. Built-ins moved to `agents/author.agent.md`, `primary.agent.md`, `specialist.agent.md`, `checklist.agent.md`, and `combined.agent.md`. Legacy `<name>.md` files with a first-line `# Label` are still accepted, so existing `agents_path` setups keep working.
- **New skill file format — `skills/<name>/SKILL.md` with frontmatter** — one folder per skill; frontmatter `name` (skill id) and `description` (shown in the prompt). The built-in `security` skill was rewritten with richer guidance (trust boundaries, client vs server enforcement, workflow/CI permissions, evidence-based reporting). Legacy flat `<name>.md` skill files are still accepted.
- **Recursive skill discovery (`**/*.md`)** — the skills folder (built-in `skills/` and your `skills_path`) is now scanned recursively: every `*.md` file at any depth (up to 5 levels) becomes a skill. `SKILL.md` uses its parent folder name as the id; any other `<name>.md` uses the file name; frontmatter `name` overrides both. Organize skills into nested team/topic folders freely.
- File-name collisions: later definitions override earlier ones (built-in → `skills_path` → `custom_skills`).

## Notes

- **Why the major bump**: the built-in file layout changed (`agents/*.md` → `agents/*.agent.md`, skills moved into per-skill folders). If you maintain your own copies of these files (via fork or `agents_path`), review the new format — the old format still loads, but new files should use frontmatter.
- Pin with `n-devs/ai-code-review@v5` (or `@v5.0.0`).
